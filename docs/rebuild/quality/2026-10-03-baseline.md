# Quality baseline before 5d (3 October 2026)

The owner asked on 3 October 2026 for a record to compare against, in case the 5d changes lower output quality. Those changes (V6, V8, V9 and V10) remove or narrow module output. The record is `2026-10-03-baseline.json`, beside this file. It covers every accepted artifact from the 2 and 3 October live runs: 9 artifacts from 9 runs. Each was read only from its run database on the persistent dev server. The artifacts stay as blobs under `.dev-data/qualification-blobs/` in the main checkout and are not committed. Each entry gives its blob paths and its artifact and record digests.

**The baseline mixes models**, so a difference between one entry and another can come from the model rather than the build. The models are `openai/gpt-6-luna-pro` (L1c, L2, L4), `openai/gpt-6-luna-pro:nitro` (N2, N3, N5), `openai/gpt-6-luna` at high effort (P1) and `deepseek/deepseek-v4.1-flash` at low effort (P3). The live loop runs on gpt-6-luna at high effort, and P1 is the only baseline answer from that configuration. Every artifact was produced under bundle `2480e369` (the `credit_os_authority_bundle_sha256` value in its front matter). All of them were read under bundle build `fa90657d` (`reader_build`), so register location uses the post-5c contracts.

## Comparing a later answer

```bash
uv run python scripts/quality_compare.py extract <artifact.md> --set qualification/<set> --record <record.json> > new.json
uv run python scripts/quality_compare.py compare docs/rebuild/quality/2026-10-03-baseline.json new.json
```

The record is the host's record blob that sits beside the artifact (`artifacts.record_sha256`). Without it, the citations and the citation, projection and readiness keys are reported as unmeasured: the report prints "citations unmeasured" and "answer keys unmeasured" with the count of each kind of key it could not check, so a lost key is never read as kept. `compare` also accepts a file with an `artifacts` list. It reports each record against the baseline answers for the same module and set, and it only informs: it exits non-zero only on a usage error.

LARGE is measured against the floor of those baseline answers. A difference is flagged only when the new answer falls below every one of them, because the baseline mixes models. A new answer is flagged LARGE when any of these holds:

- it drops a register that every baseline answer carried and the module's contract still requires;
- it misses an answer key that every baseline answer met;
- its `qa_status` or `committee_status` is worse than the worst baseline value (`Passed` < `Restricted` < `Blocked`; `Committee Ready` < `Draft Only` < `Requires More Work` < `Insufficient Information` < `Restricted` < `Blocked`);
- its `confidence_score` is at least 10 below the lowest baseline score;
- its anchored citations are at least 50% below the lowest baseline count.
- its distinct figures (every table's, less those held only by a register its module no longer requires) are below 80% of the lowest baseline count and at least 5 fewer (the floor keeps one year or page cell from flagging CP-0).

**Distinct figures** (added in 5d-2's review, 3 October 2026) count the different figures in the handoff's tables: every body cell that is one figure counts once by its magnitude, so `(335)`, `-335` and `335` are one. Removing a table that only repeats figures held elsewhere leaves the count unchanged; losing a fact found nowhere else lowers it. The baseline entries carry the count, read from the same blobs: CP-0 4 to 10, N2's CP-1 170. It is reported on every comparison. Since F482 (Task 5d-5) each record also keeps `figures_by_table`: each table's figures, as 16-hex truncated hashes (not printed; a small number is recoverable from its hash by trying every candidate, and the corpus is public), under the register ID its nearest heading leads with, or `""` for a table whose nearest heading leads with no ID (a front table). A table with no heading of its own inherits the nearest heading's label, so a tagged interface table after another register's table counts under that register (CP-1's required-register baseline is 164 for that reason). The label is read from the heading, not from a contract, so a retired register keeps its own, and a table under a retired heading is excluded (no stored answer has a second table under a retired heading). `compare` counts every table's figures less those found only in a register that a record's contract named and the new answer's module no longer requires (CP-0's P1, P2, P4, P6, P7 and P8, D97; CP-1's T4.7, D95), on both sides, and prints that total and, beside it, the count in the registers the module still requires; LARGE is judged on the total. A figure a retired register shares with a kept table stays, and so does every figure in a front table or interface table, so dropping one shows. A record without the field falls back to the whole-table count. The baseline entries gained the field on 3 October 2026, read from the same blobs; no other value changed. Under it, the CP-0 baselines hold 4 to 8 figures (P4's triage scores left out) and N2's CP-1 170 (164 in required registers; T4.7's figures are all held elsewhere). Its blind spots: magnitudes are deduplicated across units, so 120 in USD millions and 120 in percent are one figure; a cell carrying a unit, tag or word beside the figure (`USD 1,240.0m`, `[Calculated] 3.66x`) is not counted; figures in prose are not counted.

Every other change is reported under the module without the LARGE flag. That covers registers added, row counts outside the baseline range, keys gained, keys lost that only some baseline answers met, and bytes.
