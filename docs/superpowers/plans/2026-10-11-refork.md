# Re-fork onto current caos-databricks: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task by task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a `refork` branch: the current caos-databricks tip with its history,
Phase 1 replayed on top, and hardening H1–H3. All gates and the container smoke exit 0,
and a PR to `main` is opened.

**Architecture:**
- `refork` starts at upstream's tip **B**.
- The old fork history joins it through a `-s ours` merge, so `main` later
  fast-forwards with no force-push.
- Phase 1's commits are cherry-picked one group at a time, with conflicts resolved
  "upstream wins, Firebase re-applied on top".
- Hardening lands as separate, test-first commits.

**Tech stack:** git, uv, Python 3.13, pytest, Postgres 17 via `docker compose`, Node
(`.node-version`), Docker, the Firebase CLI (`npx -y firebase-tools@latest`).

**Spec:** `docs/specs/2026-10-11-refork-design.md`. Background:
`docs/specs/2026-10-04-firebase-design.md` and
`docs/research/2026-10-11-firebase-features-review.md`.

## Global constraints

- Python `>=3.13,<3.14`. Every tool runs through `uv run`.
- No new dependency without an FD entry in `docs/decisions.md`.
- Suppressions (`noqa`, `type: ignore`, `nosec`, `pragma`, skips) may only fall
  (`tests/gate_baseline.json`). No gate is loosened to pass.
- Typed refusals only. Never `str(exc)` on the wire or in a log. Never log or print a
  token, a password or document text.
- Conflict rule: **upstream's version wins; the Firebase change is re-applied on top
  with the smallest footprint.** `uv.lock` is regenerated with `uv lock`, never
  hand-merged.
- No stub or fake value standing in for real behaviour. No catch-all that hides a
  failure unless the fail-open is documented and logged.
- Every task report ends with a `Not verified:` line and the ledger line
  `agent=<name> fix-rounds=<n> gates-first-pass=<y|n>`.
- Every commit message ends with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Never push, and never open a PR, except in Task 9, from the terminal pane. Merges
  are the owner's.
- Test Postgres:
  `CAOS_TEST_POSTGRES_URL=postgresql://postgres:local-test-admin-only@127.0.0.1:55437/postgres`
  with `CAOS_REQUIRE_POSTGRES=1`, after `docker compose up -d --wait`.

### Replay procedure (used by Tasks 1–4)

For each commit in the task's list, in order:

```bash
git cherry-pick -x <sha>
```

- **Clean pick:** run the task's tests.
- **Conflict:** the controller dispatches the task's implementer with:
  - the conflicted file list (`git diff --name-only --diff-filter=U`);
  - the original commit (`git show <sha>`);
  - the conflict rule;
  - the task's resolution notes.

  The implementer resolves, runs the task's tests, then `git add` and
  `git cherry-pick --continue`.

Skipped for good: **9929b80** (B already has the vendored skills) and **bc57dbf** (D9:
the real upstream commits are in history now).

The reviewer checks replay fidelity with
`git range-diff <first-original>^..<last-original> <first-replayed>^..HEAD`. Every
semantic difference must be explained by the conflict rule.

The resulting `chat_model` must read:

```python
def chat_model(*, endpoint: str | None = None) -> BaseChatModel:
    """The production chat model: `ChatCopilot` for a Copilot model (upstream D77,
    kept inert here), else OpenRouter's OpenAI-compatible API (FD5, FD8, FD16).

    The key is read at the call and never stored or printed. The reasoning
    effort and the provider pin travel in the request body, so the identity
    a verdict binds names what the model actually received.
    """
    name = endpoint or configured_endpoint()
    target = copilot.parsed(name)
    if target is not None:
        if target.platform != copilot.PLATFORM:
            raise Refusal(RefusalCode.PROVIDER_NOT_CONFIGURED)
        return copilot.ChatCopilot(model=name)
    key = os.environ.get(OPENROUTER_KEY_ENV)
    if not key:
        raise Refusal(RefusalCode.PROVIDER_NOT_CONFIGURED)
    base_url = model_base_url()
    from langchain_openai import ChatOpenAI

    body: dict[str, object] = {}
    effort = reasoning_effort()
    if effort:
        body["reasoning"] = {"effort": effort}
    order = provider_order()
    if order:
        body["provider"] = {"order": list(order), "allow_fallbacks": False}
    # The same deadline and no retry below the seam (F40): a retry is the
    # caller's reservation.
    return ChatOpenAI(
        base_url=base_url,
        api_key=SecretStr(key),
        model=name,
        max_completion_tokens=MAX_COMPLETION_TOKENS,
        timeout=TIMEOUT_SECONDS,
        max_retries=0,
        extra_body=body or None,
    )
```

Use FD numbers in comments from the start (the D→FD rename is Task 5). If upstream's
`reasoning_effort()` now differs in name or signature, use upstream's and adapt the
call.

```python
#!/usr/bin/env python3
"""Create a CAOS sign-in with its email verified, or verify an existing one (FD19).

The owner runs this on their own machine with application-default credentials
(`gcloud auth application-default login`, then
`gcloud auth application-default set-quota-project <project>`); it never ships in
the image. The password is read without echo, sent once to Firebase, and never
printed or logged. A refusal prints only the error's class.
"""

from __future__ import annotations

import argparse
import getpass
import sys
from collections.abc import Callable

import firebase_admin
from firebase_admin import auth

REFUSALS = (auth.EmailAlreadyExistsError, auth.UserNotFoundError, ValueError)


def parser() -> argparse.ArgumentParser:
    """The command line: `--project <id> create|verify <email>`."""
    root = argparse.ArgumentParser(description="Create or verify a CAOS sign-in.")
    root.add_argument("--project", required=True, help="Firebase project id")
    commands = root.add_subparsers(dest="command", required=True)
    commands.add_parser("create", help="create an email/password user, verified").add_argument("email")
    commands.add_parser("verify", help="mark an existing user's email verified").add_argument("email")
    return root


def create(email: str, password: str) -> str:
    """The new user's uid; the user is created with `email_verified` true."""
    return str(auth.create_user(email=email, password=password, email_verified=True).uid)


def verify(email: str) -> str:
    """The existing user's uid, after marking the email verified."""
    uid = str(auth.get_user_by_email(email).uid)
    auth.update_user(uid, email_verified=True)
    return uid


def main(argv: list[str] | None = None, read_password: Callable[[str], str] = getpass.getpass) -> int:
    """Run one command; 0 on success, 1 on a refusal (class name only on stderr)."""
    args = parser().parse_args(argv)
    firebase_admin.initialize_app(options={"projectId": args.project})
    try:
        if args.command == "create":
            password = read_password("Password: ")
            if read_password("Repeat password: ") != password:
                print("create: refused (passwords differ)", file=sys.stderr)
                return 1
            uid = create(args.email, password)
        else:
            uid = verify(args.email)
    except REFUSALS as refused:
        print(f"{args.command}: refused ({type(refused).__name__})", file=sys.stderr)
        return 1
    print(f"{args.command}: {args.email} uid={uid} email_verified=true")
    return 0


if __name__ == "__main__":
    sys.exit(main())
```
