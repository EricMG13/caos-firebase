# Book UI: implementation plan (Plan 4 of 4)

> **For agentic workers:** REQUIRED SUB-SKILL: use superpowers:subagent-driven-development to implement this plan task by task. Steps use checkbox (`- [ ]`) syntax.

**Goal:** the desk-wide Book is one row per issuer with locked issuer and period columns, a column chooser over every stored identifier and metric, filters, a basis switch, sorting, view state in the URL, an issuer history disclosure, and open actions.

**Architecture:** this is pure client-side work over Plan 3's `BookDocument`, with no new endpoints.
- `book/view.ts` holds the view state, pure and round-tripped through `URLSearchParams`.
- `book/filter.ts` holds the predicates and sorting, pure.
- `BookSection.tsx` composes them.
- The last view is remembered in `localStorage` (try/catch, with the URL winning).

**Spec:** `docs/superpowers/specs/2026-10-10-book-model-redesign-design.md` B6, B12–B15 and the layout rule (one value per cell: each agency's rating and outlook, and each basis, in its own column).

## Global constraints

- Plan 2's frontend constraints apply: CSP, no new dependency, `check-tested.mjs`, and the a11y run at 320px and in light and dark.
- **Native controls:** `<select multiple>` or a checkbox list for multi-select, and `<input type="number">` for ranges. A Base UI `Popover` may host the column chooser (it's already in `node_modules/@base-ui/react`, used directly as `evidence/Overlay.tsx` does).

### Task 1: view state and URL round-trip

**Agent:** `mx-feature`.

**Files:** create `frontend/src/sections/book/view.ts`; test `frontend/tests/unit/book-view.test.ts`.

**Interfaces:**

```ts
export type Basis = "LTM" | "PF_LTM" | "BASE_FY1" | "DOWNSIDE_FY1";
export type ColumnKey = `id:${IdentifierKey}` | `m:${string}`;   // m:<line_id>[@<Basis>]; IdentifierKey below
export type IdentifierKey = "issuer_name" | "reporting_period" | "issuer_id" | "sector" | "industry_group" | "domicile"
  | "composite" | "composite_bucket" | "moodys" | "moodys_outlook" | "sp" | "sp_outlook" | "fitch" | "fitch_outlook"
  | "analysis_date" | "route" | "filed" | "currency" | "case";
export type Filter =
  | { kind: "range"; column: ColumnKey; min: string | null; max: string | null }        // decimals as strings
  | { kind: "set"; column: ColumnKey; values: string[] }
  | { kind: "notch"; agency: "moodys" | "sp" | "fitch"; best: string; worst: string };
export type BookView = { basis: Basis; columns: ColumnKey[]; filters: Filter[]; sort: { column: ColumnKey; dir: "asc" | "desc" } | null; currency: string | null };
export const LOCKED: readonly ColumnKey[] = ["id:issuer_name", "id:reporting_period"];
export const DEFAULT_VIEW: BookView;   // the spec B12 defaults (see below)
export function toParams(view: BookView): URLSearchParams;
export function fromParams(params: URLSearchParams): BookView;   // unknown keys are ignored; LOCKED columns always present
```

**Default columns** (spec B12):
- issuer name, reporting period;
- sector, composite, then Moody's, S&P and Fitch, each with its outlook as a separate column;
- LTM revenue (`m:revenue`), LTM adjusted EBITDA (`m:adjusted_ebitda`), `m:adjusted_ebitda_margin`, `m:total_debt`, `m:liquidity`;
- `m:metric:net_leverage_adjusted`, `m:metric:lease_adjusted_net_leverage`, `m:metric:interest_coverage_adjusted`, `m:metric:fcf_to_debt`, `m:metric:ffo_to_debt`.

Metric columns read from the current basis. To compare FY+1 Base with FY+1 Downside side by side in one view, a metric column key may carry an explicit basis suffix, `@BASE_FY1` or `@DOWNSIDE_FY1`. The two default forward columns are `m:metric:net_leverage_adjusted@BASE_FY1` and `m:metric:net_leverage_adjusted@DOWNSIDE_FY1`.

### Task 2: filtering and sorting

**Agent:** `mx-feature`.

**Files:** create `frontend/src/sections/book/filter.ts`; test `frontend/tests/unit/book-filter.test.ts`.

**Interfaces:**

```ts
export function cellOf(issuer: BookIssuer, column: ColumnKey, basis: Basis): string | null
export function applyView(issuers: BookIssuer[], view: BookView): BookIssuer[]
```

**Rules:**
- **Range filters** compare decimals exactly with `toScaled` (`src/charts/decimal.ts`), never `Number`. A null value fails a range filter.
- **Amount columns** (unit MONEY) with no `view.currency` filter or sort only within the chosen currency (spec B13). Without a chosen currency, a MONEY range filter is inert and the UI asks for one.
- **Set filters** match exactly.
- **Notch filters** use the agency scale's index; an unrated issuer fails.
- **Sort:** decimals exactly; ratings by composite notch; nulls last whatever the direction.

**Behaviour:**
- **Toolbar:** a basis switch (segmented native radio group), Columns (the chooser: every identifier and every `metric_catalogue` entry, with the locked ones disabled), Filters (one chip per active filter; "Add filter" picks a column, then a range, set or notch editor), a currency select (shown when a MONEY column is filtered or sorted), and Reset view.
- **The table** uses `tbl dense pin-first` inside `.tscroll`, with the same sticky headers as the Model grid. Each header button sorts and sets `aria-sort`.
- **Badges:** Filed, Sources withdrawn.
- **Row actions:**
  - the issuer name links to `/analysis/?case=<case>&run=<run>`;
  - an "Open model" link goes to `/model/?case=<case>&run=<run>`;
  - "History (n)" opens `IssuerHistory`, a disclosure row listing prior entries (date, period, route, withdrawn reason).
- **View persistence:** the view syncs to the URL with `{replace: true}`. On mount with no params, restore the last view from `localStorage['caos.book.view']` (try/catch); write it on change.
- **Counts:** a footer shows "N of M issuers".
